## Part B: Critique

### Example 1: About Me dates and job title
- Proposed: Viber's About Me draft listed my Flex practicum and Teaching Assistant role as "2024 to present" and gave my iGreenData title as "Fintech Engineer".
- Decision: I changed both dates to "January 2026 to present" and the title to "Associate Engineer, then Engineer, Product & Release", and approved the rest.
- Why: The dates and title were wrong. A recruiter comparing my portfolio with my LinkedIn or resume would notice, so accuracy mattered more than wording.
- File / commit: app/about-me/page.js, commit 863d768
- Check: I opened /about-me in the browser and compared it line by line with my resume.
- Outcome: The page now shows "January 2026 to present" for both roles and the correct iGreenData title.

### Example 2: Replacing the hand-drawn map
- Proposed: A hand-drawn SVG world map with rough continent outlines, grid lines, and a white label box on every pin.
- Decision: I rejected it and asked for a dotted world map generated by the dotted-map package, with no grid lines, names shown only on hover or keyboard focus, and the empty polar areas cropped. When the dots were too faint, I asked for them to be darker.
- Why: The hand-drawn shapes looked crude and the labels cluttered the map, especially where the Bengaluru and Chennai pins overlap. It made the whole site feel less professional.
- File / commit: components/WorldMap.js, lib/journeyPins.js, commit 6a7cdb3
- Check: I reloaded the home page, hovered over and clicked each pin, and confirmed each card's link opened the right page.
- Outcome: The map now uses real geography in soft dots, the pins are clear, and every card opens and links correctly.

### Example 3: Unknown project addresses
- Proposed: A friendly not-found page for project addresses that don't exist, but Next.js 16's cache-components mode kept interfering with the dynamic project route.
- Decision: I approved turning cache-components off and having the two real project pages generated ahead of time, so any other address shows the not-found page.
- Why: The assignment requires an understandable response to an unknown value, not an error or a blank page.
- File / commit: next.config.mjs, app/projects/[slug]/page.js, app/projects/[slug]/not-found.js, commit a9d95d4
- Check: I typed localhost:3000/projects/nope in the browser, then opened both real project pages.
- Outcome: /projects/nope shows "Project not found" with a working "Back to Projects" link, and both real project pages show their own content.
